### 현재 예문 수준 라벨의 문제

`meta.level` 은 `scripts/build_example_meta.py` 규칙: `단어수≤8 & 희귀어 0 → 1`, `≤13 & 희귀어≤1 → 2`, 그 외 3. 희귀어 기준은 `zipf < 3.5`.

- **zipf 3.5 는 너무 관대하다.** B2~C1 단어도 대부분 zipf 3.5 이상이라 "희귀어 0"으로 통과한다. 표본 2만 문장에서 문장 속 내용어의 최고 CEFR을 재보니 **수준 1 문장의 17%가 B2 이상 단어를 포함**(수준 2는 35%가 B2+).
- **목표 단어 자체의 난이도를 반영하지 않는다.** 목표 단어가 C1이면 문장이 짧아도 수준 1로 찍힌다.
- **문형(문법) 난이도가 없다.** 관계절·가정법·분사구문·수동태가 있어도 길이만 짧으면 쉬움.
- 표제어 원형화가 덜 됨(`owls` 처럼 복수형이 희귀어로 집계되는 사례).
- 출처는 `dict`(기존 수집) / `gen20260930`(AI 생성) 두 값뿐, 라이선스·검수 여부 칸이 없다.

엄격 재분류(수준1 = 기존 1 & 최고 CEFR ≤A2, 수준2 = 기존 ≤2 & ≤B2, 나머지 3) 시 서점 단어 실효 개수:

|---|---|---|---|---|
| 쉬움(1) | 6,058 | 179 | 2,530 | 23,133 |
| 보통(2) | 8,012 | 1,966 | 164 | 11,006 |
| 어려움(3) | 8,158 | 80 | 10 | 21,743 |

## ② 예문 스키마 고도화안 (`voca_example_meta` 확장, 사전 DB)

새 테이블을 만들지 않고 기존 파생 테이블에 칸을 더한다(`migrations_dict`, 모두 nullable → 기존 흐름 무영향).

| 칸 | 타입 | 의미 · 산출(전부 규칙 기반, AI 0) |
|---|---|---|
| `cefr` | CHAR(2) | 문장 CEFR = 아래 `difficulty` 구간화 |
| `difficulty` | SMALLINT 0–100 | 합성 점수(아래 식). 정렬·근접 선택용 |
| `vocab_max_cefr` | TINYINT 1–6 | 목표 단어 제외 내용어의 최고 CEFR |
| `vocab_p90_zipf` | FLOAT | 내용어 zipf 하위 10% 값(가장 어려운 쪽) |
| `target_cefr` | TINYINT | 목표 단어 CEFR (`voca_label`) |
| `clause_count` | TINYINT | 절 수(spaCy 의존구문: ROOT+ccomp/advcl/relcl/acl) |
| `patterns` | JSON | 문형 태그 리스트(아래 표) |
| `license` | VARCHAR(24) | `own-gen` / `tatoeba-cc-by` / `tatoeba-cc0` / `dict-legacy` |
| `source_ref` | VARCHAR(64) | 외부 원문 ID(Tatoeba 문장 번호 등) |
| `qa` | TINYINT | 0 미검수 / 1 자동검증 통과 / 2 사람·AI 검수 |
| `meta_ver` | TINYINT | 라벨 규칙 버전(재계산 판단) |

`difficulty` 식(초안, 가중치는 ⑥에서 실데이터로 1회 보정):

```
difficulty = 4·max(0, 단어수−5) + 12·(vocab_max_cefr−1) + 6·(target_cefr−1)
           + 8·(clause_count−1) + Σ 문형 가중치          (0~100 클램프)
cefr: <20 A1 · <35 A2 · <50 B1 · <65 B2 · <80 C1 · 그 외 C2
기존 level(1/2/3)은 A1–A2→1, B1→2, B2+→3 으로 재계산해 호환 유지
```

문형 태그(spaCy `en_core_web_sm` 품사·의존·형태소 규칙으로 판정, 사전 정의 20종 내외):

| 태그 | 판정 규칙 예 | 가중 |
|---|---|---|
| `present_simple` `past_simple` `future_will` | 동사 Tense/조동사 | 0 |
| `progressive` `perfect` | be+VBG / have+VBN | 3 / 6 |
| `modal` | MD | 2 |
| `passive` | nsubjpass·auxpass | 6 |
| `question` `imperative` `negation` | 문장부호·어순·neg | 1 |
| `to_infinitive` `gerund` | xcomp+to / VBG 명사적 | 3 |
| `relative_clause` | relcl | 8 |
| `conditional` `conditional_unreal` | if+advcl / would+have | 6 / 12 |
| `comparative` `superlative` | JJR/JJS | 2 |
| `participle_clause` | 문두 VBG/VBN advcl | 10 |
| `phrasal_verb` | prt 의존 | 3 |
| `reported_speech` `that_clause` | ccomp+say류 / mark=that | 6 |

> 일한은 같은 칸을 쓰되 `cefr` 대신 JLPT 대역(N5~N1)을 `vocab_max_jlpt`·`difficulty` 로 계산(형태소 = fugashi+unidic-lite, 단어 JLPT = `voca_ja.jlpt`). 문형 태그는 2단계로 미룬다.

## ③ 사용자 수준 모델 (사용자 DB)

두 축만 둔다: **어휘 수준**(문장 단어를 얼마나 아나)과 **문형 숙련도**(어떤 문장 구조를 소화하나).

### 신규 테이블 `user_level_profile` (user_id × lang, 1행)

| 칸 | 의미 |
|---|---|
| `vocab_theta` FLOAT | 어휘 수준 0–100 (= 예문 `difficulty` 와 같은 눈금) |
| `vocab_cefr` CHAR(2) | theta 구간 |
| `pattern_mastery` JSON | `{태그: {n, correct, ema}}` |
| `sentence_theta` FLOAT | 문장 문제(빈칸·조각·받아쓰기) 전용 수준 |
| `evidence_n` INT | 누적 근거 수(신뢰도) |
| `updated_at` | |

### 추정 방식 (규칙 기반, 매 `/study/log` 에서 O(1) 갱신)

1. **초기값**: 온보딩 `level_id`(1~4 → theta 15/30/50/70). 없으면 25(A2).
2. **어휘 근거**: 학습 로그의 단어 CEFR별 정답률(FSRS rating ≥3 비율). 정답률 80% 이상인 가장 높은 CEFR 대역을 vocab_cefr 로. "아는 단어"는 내 단어장 reps≥1 **+ vocab_cefr 이하·zipf ≥ 해당 대역 하한인 사전 단어 전체**로 확장(→ 초보도 the/go/house 를 아는 것으로 처리).
3. **문장 근거**(Elo식): 문장 문제 하나 = (사용자 sentence_theta vs 문장 difficulty) 대결.
   `기대 = 1/(1+10^((d−θ)/25))`, `θ += K·(정답−기대)`, K=4(evidence<30이면 8). 시간 초과(>p90)는 정답이라도 0.5 처리.
4. **문형 숙련**: 그 문장의 `patterns` 각각에 정답 EMA(α=0.2) 갱신. n≥5 & ema<0.5 = 약한 문형.
5. **체감 신호**: 결과 화면/문제 헤더에 "너무 어려워요" 1탭(선택) → θ −5, 그 문장 30일 제외.

`user_study_log.example_hash` 기록이 전 문장 문제에서 빠짐없이 채워지는지가 전제 — ⑥ 0단계에서 확인.

## ④ 예문 선택 로직 (`example_select.py` 교체 지점)

목표 난이도 = **사용자 수준 + 단어 숙련도 보정**, 작물 단계 단독 결정은 폐기.

```
target_d = sentence_theta
         + {씨앗/처음: −15, 새싹: −5, 잎: 0, 당근: +8}[작물 단계]
         + (최근 3문제 연속 오답 ? −10 : 0)
허용 구간 = target_d ± 10  (후보 0개면 ±20, 그래도 0이면 가장 쉬운 것)
```

점수(낮을수록 우선, 기존 구조 유지):

| 항목 | 가중 |
|---|---|
| 최근성(30일 내 본 문장) | 100 (기존) |
| `|difficulty − target_d|` | 1점/눈금 |
| 모르는 내용어 수(확장된 아는 단어 기준) | 8/개, **2개 초과 후보는 제외**("새 단어는 목표 단어 1개" 원칙) |
| 약한 문형 포함 | −5 (적당히 연습), 단 씨앗 단계는 +10(피함) |
| `qa=0` 외부 코퍼스 문장 | +5 |

- **새 씨앗 심기(plant)**: 현행 엄격 기준(조각≤7·수준1·희귀어0)을 `difficulty ≤ target_d−15 & 모르는 단어 0`으로 치환.
- 후보 부족(허용 구간에 0~1개)은 로그로 남겨 ⑤의 생성 우선순위 입력으로 쓴다(`example_gap` 집계).

### 단계 C — AI(Sonnet 서브에이전트) 1회 배치

AI는 두 작업만 한다. **(C1) Tatoeba 채굴 문장의 한국어 해석 + 목표 단어 태깅**, **(C2) 채굴로도 못 채운 칸의 문장 생성.** 생성은 9/30 파이프라인(`db/sentence-gen/` PROMPT·validate·조각 검증)을 그대로 재사용한다.

설계 (9/30 교훈 반영: 25단어 배치에 검증 무제한 → 배치당 15만 토큰·18분이었고, 검증 2회 제한·에이전트당 3배치로 ~4.2만 토큰까지 내려감):

| 항목 | 값 |
|---|---|
| 입력 | 단계 A가 만든 부족분 목록만. 배치 파일 = 고정 JSON(단어·뜻·품사·대역·필요 수·금지 단어 목록=대역 초과 어휘) |
| 배치 크기 | C1 번역 100문장/배치, C2 생성 25단어/배치 |
| 에이전트당 | 3배치, 동시 실행 상한은 세션 한도 보고 결정 |
| 자기 검증 | 에이전트가 `validate.py` 1회 실행 → 실패분만 1회 재작성(최대 2회), 그래도 실패면 제외 표시하고 넘김 |
| 코드 검증(투입 전) | 목표 단어 태그 1개 · ② 라벨 재계산 결과가 요청 대역과 일치 · 대역 초과 어휘 0 · 한국어 해석 비어있지 않음/한글 비율 · 조각 데이터 생성 가능 · 중복 해시 없음 |
| 표본 감사 | 대역별 30문장씩 90문장 독립 심사(Opus 1회) — 불합격률 5% 넘으면 해당 프롬프트만 수정 후 실패 배치 재실행 |
| 투입 | `meta.license=own-gen`, `qa=1`, 사전 발행은 admin `dict_manage` 경로(1회 발행) |

우선순위와 예상 규모(토큰은 9/30 실측 단가로 추정: 생성 27.7M/48,915문장 + 조각 ~20M → **문장당 ~1.0k**, 번역+태깅 ~0.3k/문장):

| 순서 | 범위 | 예상 문장 수 | 예상 토큰 |
|---|---|---|---|
| P1 | 서점 단어 8,167 × 쉬움·보통 2개 확보(엄격 라벨 기준 부족분) | 2,694 | ~2.7M |
| P2 | 서점 단어 쉬움·보통 5개 확보 | ~31,400 (채굴 후 감소) | ~31M 상한 |
| P3 | 서점 B2+ 단어 어려움 2→5 | ≤8,200 (B2+ 서점 단어 2,733개) | ~8M 상한 |
| P4 | 비서점 A1~B2 단어(예문 ≤2, 7,853개) 쉬움·보통 2개 — 채굴 위주 | ~15,700 중 채굴 후 잔여 | 채굴 후 산정 |
| P5 | 일한 JLPT N5~N3 수준 메타 + 쉬움 2개 | 채굴 후 산정 | 채굴 후 산정 |

**P1 만 먼저 1회 실행하고 체감 확인 후 P2 이후를 결정**한다(사용량 절약). P1·P2 는 단계 B 채굴분을 빼고 남은 칸만 생성하므로 실제 생성량은 위보다 줄어든다.

## 사용자 결정 필요 사항

1. **"레벨" 정의** — 문장 CEFR 3대역(쉬움 A1–A2 / 보통 B1 / 어려움 B2+)으로 해도 되는가? (5단계 CEFR 별로 5개씩이면 생성량이 약 1.7배)
